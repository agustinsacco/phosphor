# 2026-08-28 — The mirror still spoke pre-0.84.0, so no tool card ever got a name early

Re-verified `shared/rpc.ts` against **pi 0.84.4** (latest published; 0.84.1 is
what this machine has installed, and `MIN_PI_VERSION` stays there).

The headline: **nothing in Phosphor was broken by the version bump itself.** The
0.84.1 → 0.84.4 delta on the RPC surface is one added command. What _was_ wrong
is that the mirror still described the **pre-0.84.0** streaming shape, a drift
this repo believed it had closed — `TRACKER.md` claims `get_entries`/`get_tree`
were mirrored and the cumulative snapshot removed. Neither was true.

## What pi actually sends

pi's stdout is not its internal `AgentSessionEvent`. It passes through
`toJsonEvent` (`dist/modes/json-event.js`), and the authoritative stdout type is
`dist/modes/json-event.d.ts` — **not** `rpc-types.d.ts`, which describes the
internal shape. That distinction is why the drift survived: diffing against
`rpc-types.d.ts` shows a `partial` that never reaches the wire.

| pi     | RPC surface change                                                   |
| ------ | -------------------------------------------------------------------- |
| 0.84.0 | dropped `message_update.message` and `assistantMessageEvent.partial` |
| 0.84.2 | re-added cumulative `usage` on `message_update` (#7982)              |
| 0.84.3 | put `id` + `toolName` on `toolcall_start` (#7953)                    |
| 0.84.4 | added the `clear_queue` command                                      |

## The bug that cost something

`reducer.ts` read tool-call identity from `assistantMessageEvent.partial` in
`toolcall_start` and again in `toolcall_delta`. pi stopped sending `partial` in
0.84.0, so **both calls were permanently dead** — `revealedToolCall()` returned
`null` on every event, always.

Consequence: every streaming tool card keyed itself under a `pending-*`
placeholder with `toolName: null`, and stayed there — "Preparing tool…" — for
the whole argument payload, until `toolcall_end` or `tool_execution_start`
arrived. For a large `write`, that is minutes of wall clock. `toolIdentity.ts`'
own docblock described the 0.84.0 behaviour as live ("Anthropic direct puts both
in the first `partial`"), which is how the dead path read as intentional.

0.84.3 is the supported fix for exactly this, and Phosphor was not reading it. So
the fix is to read `delta.id` / `delta.toolName` off `toolcall_start` — one
`revealedFromStart()` replaces both dead call sites. It is read as **optional**
and needs _both_ fields before revealing, so a 0.84.1 install (or Bedrock-routed
Claude, which withholds identity until `toolcall_end`) still falls back to the
placeholder rather than rendering a title-less card.

## Also fixed in the mirror

- `message_update.message` was typed **required** and never sent. Nothing read
  it — lucky, not by design — but the type invited a crash. Replaced with
  `usage?: Usage`.
- Missing events: `bash_execution_update`, `summarization_retry_scheduled`,
  `summarization_retry_attempt_start`, `summarization_retry_finished`. Unknown
  events land in a `default` branch, so these were silently dropped, not
  crashing. `bash_execution_update` is the one worth wiring later: it is the
  streamed output of a direct `bash` command.
- Missing commands: `get_entries` (+`since`), `get_tree`, `clear_queue`, with
  `RpcResponseDataMap` entries so the compile-time guard still covers them.
  Their entry/node shapes are `unknown[]` on purpose — no surface renders them
  and half-mirroring a recursive on-disk format is how specs drift again.

## Deliberately not done

- **`MIN_PI_VERSION` stays `0.84.1`.** 0.84.2→0.84.4 is purely additive and the
  two new fields are read as optional, so raising the floor would block users
  on a working install for no gain.
- **`clear_queue` has no UI.** It needs a queue affordance to drain into; the
  renderer currently only displays `queue_update`. Wiring it is its own change.
- **`mockPhosphor.ts` has no `clear_queue` case** — the browser harness can't
  render the affordance, so it needs nothing until the affordance exists.
- The e2e stub cannot catch this class of regression (it does not implement the
  wire contract). The guard is `toolIdentity.test.ts` asserting both the named
  pi-0.84.3 case and the anonymous fallback.
